## 4-lens audit

### Lens 1 — Architecture (M1's design-doc-specified primary lens)

**PASS.**

- **Does the pipeline cleanly extend `provisionVM` rather than fork?**
  YES. The bootstrap module reuses `provisionVM`'s helper patterns
  (stage-dev-certs shared-CA-or-tempdir model, copyCertsIntoVm guest
  path layout, waitForGuestAgent polling cadence) by re-implementing
  them locally rather than refactoring `provisionVM` itself. The
  design-doc directive ("Prefer NOT to refactor — wrap and compose
  rather than break the existing surface") is honoured: `provision.ts`
  is unchanged. Trade-off accepted: light code duplication in
  `stageDevCerts` / `copyCertsIntoVm` / `waitForGuestAgent` /
  `waitForVmReady`; documented as a deliberate choice in the module
  docstring; v0.6 may extract a shared `guest-mtls-staging.ts` once
  the bootstrap path stabilises.

- **Does resumability cleanly compose with idempotency?**
  YES. The `runPhase` helper is a single chokepoint that
  (a) probes the journal for prior completion of `phase`,
  (b) skips and emits a `phase_skip` event when complete,
  (c) executes the closure + records success on the journal otherwise,
  (d) records a typed failure marker on exception, persists, rethrows.
  Phase ordering is canonical (`PHASE_ORDER`); idempotency is per-phase
  rather than per-pipeline. `--force` is the single explicit override;
  the failure model is "leave-the-VM" identical to `provisionVM`.

- **Versioning + forward compat.** `bootstrap-win11-state.ts` carries
  `stateVersion: 1`. Reader tolerates unknown additive fields (forward
  compat); rejects a newer `stateVersion` with a clear error. M2's
  Unattended.xml seed-ISO bookkeeping + M4's libvirt-specific firmware
  state will be additive (no breaking bump expected).

- **Backend abstraction.** Phase 4 (set_firmware) is the only place
  the pipeline touches a backend-optional method; it surfaces a typed
  `BootstrapWin11Error` with remediation hints when the backend
  (libvirt today) lacks `setVmFirmware`. The pipeline does NOT
  hard-code the Hyper-V backend type; M4's libvirt shim will plug
  into the existing call site with no pipeline changes.

- **State-file path hygiene.** `bootstrapStatePath` rejects VM names
  with path separators, NUL, or reserved-name forms (`.` / `..` /
  empty). A hostile VM name cannot escape the state dir.

- **Concurrency.** Q8 honoured via `O_EXCL` lockfile. Cross-worktree
  isolation is a known limitation (same caveat as `task_start`
  collision detection): two operators with separate worktrees would
  both pass the host-lock probe if their `projectRoot` paths differ.
  Documented in the lock-acquisition comment.

### Lens 3 — Product (operator experience + failure surfaces)

**PASS.**

- **One-verb end-to-end.** `signalman vm bootstrap-win11 <name>` is
  the single entry point. Operator does NOT need:
  - elevated PowerShell for `Set-VMFirmware` (Q-set-firmware shipped
    in `b0ec24c`);
  - elevated PowerShell for `bcdedit /set testsigning` (phase 7
    routes through `backend.executeCommand` with scenario per-VM
    creds);
  - hand-rolled RDP for MSI install (phase 11 is `copyFileToVM` +
    silent msiexec `/i ... /quiet /norestart`).
- **Progress visibility.** `onProgress` emits four event kinds
  (`phase_start` / `phase_skip` / `phase_complete` / `warning`); the
  CLI streams them to stderr while keeping stdout reserved for the
  `--format json` envelope. Operator can grep stderr for
  `[bootstrap-win11:<phase>]` to bisect a failure.
- **Failure remediation.** Every `BootstrapWin11Error` carries a
  `remediation: string[]` field populated for the cases an operator
  is most likely to hit:
  - `set_firmware` (no backend support): two hints — switch backend
    or wait for M4.
  - `enable_testsigning` (non-zero bcdedit exit): two hints — check
    creds, verify Secure Boot Off.
  - `verify_testsigning` (No after reboot): two hints — confirm
    Secure Boot, check OEM testsigning lock.
  - `resolve_msi` (missing or nonexistent path): two hints with the
    actual path so operators can copy-paste an `ls` check.
  - `install_msi` (non-zero msiexec): two hints — verify cert trust,
    run msiexec interactively.
- **Idempotency contract.** Re-running an already-bootstrapped VM is
  a fast no-op (~ms in the test suite; bounded by `listVMs` +
  `listCheckpoints` in production). Resumable mid-pipeline. `--force`
  is the explicit reset.
- **Scenario fixture.** The shipped `bootstrap-win11-setup.yaml`
  documents the per-VM credential routing with `${secret:...}`
  substitution and explains why `pre_started: false` is required
  for the bootstrap-owned-lifecycle path.

### Lens 4 — Security

**PASS with one note.**

- **Set Secure Boot Off + testsigning On is the deliberate VM
  posture for this pipeline.** This is called out explicitly in the
  module docstring AND the design doc Non-goals. The pipeline output
  is a "test VM" — operator-facing documentation (M5 deferred) will
  reinforce that the resulting checkpoint should not be used for
  production trust decisions.
- **Test-signing certificate is operator-supplied (`--cert <path>`
  or `SIGNALMAN_TEST_SIGNING_CERT`).** The pipeline accepts the path,
  persists it in the state file for forensic context (NOT the cert
  content), but does NOT yet provision the cert into the guest — that
  lands in M2 alongside Unattended.xml so the first-boot can install
  the cert into the guest's trusted root store. M1 assumes the
  operator has manually trusted the test-signing CA in the template
  VHDX. **NOTE**: this is a known gap — without cert provisioning,
  the MSI install in phase 11 will fail unless the template was
  pre-prepared. Documented in `BootstrapWin11Opts.testSigningCertPath`
  docstring + the example fixture comment block.
- **Per-VM credentials never touch the CLI argv.** The bootstrap
  pipeline relies on scenario-level `credentials:` + `${secret:...}`
  substitution. The CLI exposes no `--username` / `--password` flags
  on `bootstrap-win11`; operators with non-standard accounts must
  invoke the verb from a scenario context where the per-VM
  credentials are declared.
- **Host lock prevents concurrent firmware mutation on the same
  hypervisor.** Q8 implementation. Stale-PID steal is bounded to
  files where the JSON lists a pid that fails `process.kill(pid, 0)`;
  corrupt files are stealable but only because they can't be
  meaningfully owned.
- **VM name validation.** `bootstrapStatePath` rejects path-traversal
  characters; an attacker who could pass a hostile VM name through
  the CLI (unlikely — the verb is operator-driven) cannot escape the
  state directory.
- **MSI auth token rotation.** When the cert bundle's auth-token file
  is reaped between phases (resume scenario), the token defaults to
  empty rather than a freshly-minted random — preserving the
  contract that the same token is consistent with what the host
  client expects. Documented in `readAuthTokenFromCerts`.

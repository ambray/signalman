## Behaviors restored or added (vs. v0.4.x libvirt)

- `executeCommand` returns real `{exitCode, stdout, stderr}`. Previously hardcoded `exitCode: 0` and `stdout = JSON envelope`. Scenarios that gate on guest exit code now actually gate.
- `copyFileToVM` / `copyFileFromVM` do real QGA `guest-file-open` → chunked `guest-file-write`/`read` → `guest-file-close` round-trips. Previously emitted non-existent `guest-file-open-write` / `guest-file-open-read` verbs that QGA rejects.
- `getStatus.guestAgentReachable` probes `guest-ping`. Previously hardcoded `false`. Orchestrator parallel-readiness waits now resolve on libvirt.
- `getVmIpAddress` walks lease → agent → arp source fallback. Static-IP and bridge-network VMs now report an IP.
- `waitForHeartbeat`, `setVmMemory`, `setVmProcessor` — optional interface methods previously missing; hyper-v parity reached.
- `createVM` from `VMConfig` (formerly `unsupported_operation`). Builds a domain XML with virtio + QGA channel; backing-file qcow2 disk created via `qemu-img`. Provisioning code paths (`provisioning/provision.ts`, `ephemeral-vm.ts`) can now use libvirt.

## Parity divergences from `hyperv.ts`

Behaviors that remain different by design (documented in design doc §Locked design):

| Method | Hyper-V semantics | Libvirt semantics |
|---|---|---|
| `setVmMemory` / `setVmProcessor` | `Set-VMMemory -StartupBytes` → next boot only on stopped VMs; live on dynamic-memory enabled running VMs | `--config` only → persisted next-boot XML; operator stops the VM to resize active state |
| `copyFile` `ProgressCallback` | Hyper-V emits heartbeat events for files past the 60s threshold (`runCopyWithProgress`) | Not wired in M2; chunked round-trip works but `_progress` is unused. Future M2.5 if real-VM testing shows operators need it |
| `createVM` | Creates a fresh empty disk via `New-VM` | Requires an existing qcow2 template path; produces a backing-file child disk |

### Finding

`vm delete` → `virsh undefine --remove-all-storage` removed the domain definition but left the backing-file qcow2 (`ws11-demo.qcow2`) on disk. Root cause: `--remove-all-storage` only removes volumes libvirt tracks in a pool, and `createVM` uses raw `qemu-img create` rather than `virsh vol-create-from`, so the disk file is invisible to libvirt's volume manager. Fix path: have `createVM` create the disk via `virsh vol-create-as` (or `vol-create-from`) so it's pool-managed; then undefine's storage cleanup works.

Workaround for now: operator manually `rm` the orphaned `.qcow2` after `vm delete`. Demo log captures one orphan that I removed manually post-run.

### Runbook for the deferred real-VM demo

The intent is to verify the full lifecycle through `signalman vm` verbs against a real libvirt KVM domain. From the repo root, with `PATH` extended for the corepack-shimmed `npm`/`npx`:

```bash
export PATH="/usr/share/nodejs/corepack/shims:$PATH"
cd host
```

1. **Fetch an Ubuntu cloud image** (~600 MB):

```bash
curl -L -o /tmp/noble-server-cloudimg-amd64.img \
  https://cloud-images.ubuntu.com/noble/current/noble-server-cloudimg-amd64.img
sudo install -m 0644 -o libvirt-qemu -g kvm \
  /tmp/noble-server-cloudimg-amd64.img \
  /var/lib/libvirt/images/noble-template.qcow2
```

2. **Build a cloud-init seed ISO** that installs `qemu-guest-agent` on first boot:

```bash
sudo apt install -y cloud-image-utils
cat >/tmp/user-data <<'CI'
#cloud-config
users:
  - name: signalman
    sudo: ALL=(ALL) NOPASSWD:ALL
    shell: /bin/bash
    ssh_authorized_keys:
      - <YOUR-PUBLIC-KEY-HERE>
packages:
  - qemu-guest-agent
runcmd:
  - systemctl enable --now qemu-guest-agent
CI
cat >/tmp/meta-data <<EOF
instance-id: signalman-ws11-demo
local-hostname: ws11-demo
EOF
cloud-localds /var/lib/libvirt/images/seed.iso /tmp/user-data /tmp/meta-data
```

3. **Register a template + provision via the host CLI**. `vm create` resolves through `.signalman/templates/<name>.yaml`; the loader keys `base_image_path` to the absolute qcow2 used as the libvirt backing file.

```bash
mkdir -p .signalman/templates
cat >.signalman/templates/ubuntu-noble.yaml <<'YAML'
name: ubuntu-noble
base_image_path: /var/lib/libvirt/images/noble-template.qcow2
memoryMB: 2048
processorCount: 2
networkSwitch: default
YAML

export SIGNALMAN_BACKEND=libvirt
npx tsx src/cli.ts vm create ws11-demo --template ubuntu-noble
```

This exercises the new `createVM` XML builder + `qemu-img` backing-file disk path. Expect:
- A new `/var/lib/libvirt/images/ws11-demo.qcow2` disk image (sparse, backed by `noble-template.qcow2`).
- A domain registered with libvirt (`virsh list --all` shows `ws11-demo`).

To wire the seed ISO into the domain (so cloud-init runs on first boot and installs `qemu-guest-agent`), attach it before starting:

```bash
virsh -c qemu:///system attach-disk ws11-demo \
  /var/lib/libvirt/images/seed.iso sda \
  --type cdrom --config
```

4. **Boot and probe** (exercises the new `waitForHeartbeat` → `guest-ping` poll loop):

```bash
npx tsx src/cli.ts vm start ws11-demo
npx tsx src/cli.ts vm wait-heartbeat ws11-demo --timeout 180000
```

5. **End-to-end command exec** (exercises real `guest-exec` + `guest-exec-status` polling):

```bash
npx tsx src/cli.ts vm exec ws11-demo -- /bin/uname -a
# Expect exitCode 0 + decoded stdout from `uname -a`.
```

6. **File transfer** (exercises real QGA `guest-file-open` → write/read → close):

```bash
echo hello > /tmp/test-up.txt
# Host → guest (default direction):
npx tsx src/cli.ts vm copy-file ws11-demo /tmp/test-up.txt /tmp/test-up.txt
npx tsx src/cli.ts vm exec ws11-demo -- /bin/cat /tmp/test-up.txt
# Expect stdout: "hello"

# Guest → host:
npx tsx src/cli.ts vm copy-file ws11-demo /etc/hostname \
  /tmp/guest-hostname.txt --direction guest-to-host
cat /tmp/guest-hostname.txt
# Expect: ws11-demo (or whatever local-hostname cloud-init set)
```

7. **Snapshot cycle**:

```bash
npx tsx src/cli.ts vm checkpoint ws11-demo --label baseline
npx tsx src/cli.ts vm list-checkpoints ws11-demo
# Should list `baseline`.
npx tsx src/cli.ts vm restore ws11-demo --label baseline
```

8. **Optional: resize**. Both resize ops update next-boot config — observe with `virsh dumpxml ws11-demo | grep -E 'memory|vcpu'` after a stop:

```bash
npx tsx src/cli.ts vm set-memory ws11-demo --mb 4096
npx tsx src/cli.ts vm set-processor ws11-demo --count 4
```

9. **Teardown**:

```bash
npx tsx src/cli.ts vm stop ws11-demo --force
npx tsx src/cli.ts vm delete ws11-demo
# Both the domain definition and /var/lib/libvirt/images/ws11-demo.qcow2
# disappear (undefine --remove-all-storage).
```

## v0.5 multi-OS (`feat/v0.5-libvirt-multios`)

Second followup, picked up 2026-05-17. Extends the libvirt backend to safely host Windows 10, Windows 11, modern Linux (BIOS + UEFI variants), and Alpine. Explicitly documents non-support for macOS (Apple EULA + ARM-vs-x86 reality).

### Profiles

| Profile | Firmware | Secure Boot | TPM | Disk bus | NIC | Clock | Notes |
|---|---|---|---|---|---|---|---|
| `linux` *(default)* | BIOS | — | — | virtio | virtio | UTC | v0.5 baseline behavior. Existing callers that omit `osProfile` get unchanged XML. |
| `linux-uefi` | UEFI | off | — | virtio | virtio | UTC | For Linux distros that need UEFI without enforcing keys. |
| `windows-10` | UEFI | off (operator may opt in) | none (operator may opt in) | virtio | virtio | localtime + Win timer hints | USB tablet, QXL video, VNC on 127.0.0.1. SATA + e1000e overrides for the no-virtio-win-staged install path. |
| `windows-11` | UEFI | **on (mandatory)** | **tpm-2.0 (mandatory)** | virtio | virtio | localtime + Win timer hints | + SMM. Operator overrides for firmware / secureBoot / tpm raise `invalid_argument` — Win11 refuses to boot without all three. |

Granular per-field overrides on every profile: `firmware` / `secureBoot` / `tpm` / `diskBus` / `nicModel`. Independent validation: `secureBoot` and `tpm` require `firmware='efi'`; `windows-11` rejects any of the three security-primitive overrides.

macOS profiles (`macos`, `macos-intel`, etc.) are rejected at `createVM` with a "use the Tart backend on Apple Silicon" message. See `docs/mac-virtualization.md §Non-option: libvirt/KVM`.

### 4-lens audit (multi-OS)

**QA lens — PASS.** Net +20 libvirt test cases (102 → 122). New coverage: per-profile `resolveOsProfileDefaults` baseline (4 cases), `buildDomainXml` profile snapshots (5 cases — linux-uefi, win10, win11, sata-override, e1000e-override), `createVM` profile integration (11 cases — backwards-compat default, win11 full XML, win11 refuses 3 distinct security-primitive overrides, win10 allows SB+TPM opt-in, win10 SATA+e1000e fallback for no-virtio-win path, macOS reject, unknown profile reject, secureBoot-without-UEFI reject, tpm-without-UEFI reject). Full suite 2989 / 13 skipped (no regressions on the other 149 files). Real-VM verification on 2026-05-17 against the local KVM proved both the Win11 platform chain (OVMF + swtpm + Secure Boot + virtio dispatched, qemu/swtpm processes spawned, OVMF nvram with MS keys provisioned, clean teardown) and Linux backwards compat.

**Architecture lens — PASS.** Profile resolution is a pure function (`resolveOsProfileDefaults`) returning a frozen `OsProfileDefaults` shape, then merged with operator overrides into a single `os` object that flows to `buildDomainXml`. No global state; trivially testable. The XML renderer remains a single function (no class hierarchy, no per-profile classes); conditional XML emission is inline and small. Template-loader pass-through is an additive change to `VmTemplate` (new optional fields) — backwards-compatible for every existing template YAML. CLI handler propagates the new fields via spread; backends that don't read them (Hyper-V, Tart, VMware) ignore silently.

**Product lens — PASS.** Closes "can we host Windows on this Linux box?" — yes, via osProfile=windows-10 or windows-11. The Win11 invariant enforcement (refusing operator overrides for firmware/secureBoot/tpm) is the right product call: Win11 setup refuses to run without all three, so silently producing a half-working VM would be the worse failure mode. macOS rejection has a clear actionable error ("use Tart") rather than a cryptic libvirt schema failure. Per-field overrides cover the real edge case of installing Windows without virtio-win staged (SATA + e1000e). The skill update lets the assistant route correctly when an operator says "spin up a Win11 box". A first-time operator can copy the Win11 template YAML from the skill, set `base_image_path` to their qcow2, and `signalman vm create win11-vm --template win11-base` produces a correctly-configured domain.

**Security lens — PASS.** No new injection surface: all profile inputs are typed and validated against fixed unions. macOS rejection happens before any pool/disk operations, so no partial state if an operator tries it. The Win11 invariant enforcement is a hard security gate: an operator cannot accidentally produce a Win11 VM with Secure Boot off, which would silently weaken the threat model the operator expected. The `--firmware='efi'` + `<feature name='secure-boot' enabled='yes'>` + `<smm state='on'>` combo is the libvirt-canonical Secure Boot chain — OVMF refuses to enforce SB without SMM, which we always emit when SB is on. swtpm runs in libvirt's per-domain sandbox (unix socket under `/run/libvirt/qemu/swtpm/`), not as a host daemon, so a compromised guest can't reach other VMs' TPM state. No new dependencies added on the runtime side; the Ubuntu 26.04 base already ships OVMF + swtpm.

### Notes on `uptimeSeconds`

PL1 only populates `memoryUsedMB`. `uptimeSeconds` stays undefined on libvirt: virsh does not expose wall-clock domain uptime via any documented stable surface. `dominfo` reports accumulated CPU time (not boot time); `domstats` doesn't carry a start-time field. Synthesizing a value from qemu-process start time or filesystem mtimes would be fragile. The interface field stays optional and documented.

### Architecture — PASS

- **Single source of truth for version.** Before WS12, `host/package.json` carried the version pin AND `host/src/http/app.ts` had a hardcoded `const VERSION = "0.2.1"` that drifted independently. After WS12, `host/src/version.ts` reads `package.json` at module init; both the CLI and `http/app.ts` consume it. Future bumps only touch `package.json`. The drift class is eliminated, not just rebumped.
- **`versionLine()` exported helper.** The CLI's `--version` output goes through a small, pure formatter that takes an optional version override. This makes fixture-based testing easy without spawning the CLI.
- **CHANGELOG structure preserved.** The new `[0.4.0]` section follows the existing Keep-a-Changelog conventions used by `[0.2.1]` and `[0.2.0]` — chronological order, sub-tag grouping, Added/Changed/Tests/Deferred subsections.
- **No new public API surface in the registry.** The registry's `package.json` bump (0.0.1 → 0.1.1) is purely a metadata correction; no code changed there.
- **CI workflow hardening, not restructuring.** M4 changed one boolean (`continue-on-error: true` → removed) and refreshed an outdated comment. No new jobs added; no existing jobs reordered.

### Security — PASS

- **No new attack surface.** The `--version` verb prints a static string read from `package.json`; no user input is parsed, no privileged operation runs. The integration test spawns `tsx` against the local source — a build-time / test-time concern, not a runtime risk.
- **Secret handling in the runbook.** `docs/runbooks/public-release.md` documents `gh secret set` invocations but contains zero secret material. The runbook explicitly notes that the four secrets stay in the operator's password manager or hardware token, out-of-band from the repo. The `base64 -w0 /path/to/cert.pfx | gh secret set WINDOWS_CERT_BASE64` command pipes the file content into gh's stdin without intermediate disk writes (no shell-history leakage of the secret bytes; the file path is on disk but the cert is the operator's own).
- **No log-leakage risks.** `versionLine()` outputs a single static string; no PII, no token material.
- **Auth posture unchanged.** WS12 does not touch `host/src/http/auth.ts`, the mTLS setup, or the bearer-auth path.
- **CI coverage gate is a defense-in-depth move.** A coverage regression sneaking through PR review could mask a code path that lost test coverage — making future security-relevant changes harder to verify. M4 closes that gap.
- **YAML-form template hardening.** The bug-report template is plain user input that flows to GitHub Issues; no security implication beyond standard issue-template hygiene.

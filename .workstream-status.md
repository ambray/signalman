## Surface delivered

Per design §13.6 (networking modes for guest reachability) and §13.7
(layered credential model — at-rest encryption layer).

**Network modes** — three values on `CloudInstanceConfig.network.mode`:

- `public_mtls` (default; back-compat): vendor assigns public IP,
  security group restricts inbound, mutual TLS authenticates the
  control-plane caller
- `aws_ssm`: AWS-only; forces `AssociatePublicIpAddress=false` regardless
  of `assign_public_ip`; control plane reaches the guest via SSM Session
  Manager port forwarding (tunneling implementation is a v0.3.x follow-up;
  this commit ships the contract)
- `azure_bastion`: Azure-only; records mode on handle; control plane
  reaches the guest via Bastion native client port forwarding

Cross-vendor mode passes raise `invalid_config` at provision time
(`aws_ssm` on Azure backend; `azure_bastion` on AWS backend).

The provisioned handle records `network_mode` so any control-plane recovery
path (re-attach to a running VM) sees the right mode without re-asking the
operator.

**Connection descriptors** (`host/src/cloud/connection.ts`):

`getConnectionDescriptor(handle, opts)` returns a tagged union with the
addressing parameters a caller needs to dial the guest:

- `public_mtls`: `{ kind, port, host? }`
- `aws_ssm`: `{ kind, region, instance_id, port }`
- `azure_bastion`: `{ kind, subscription_id, resource_group, vm_name, port }`

`withResolvedHost(descriptor, ip)` populates the public-IP host field after
the caller resolves it via `backend.getInstanceIp(handle)`.

**Per-org credentials at rest** (`host/src/cloud/credentials.ts`):

- AES-256-GCM with a 32-byte key from `SIGNALMAN_CRED_KEY` env var
  (base64-encoded). Fail-loud on missing/malformed key.
- Per-row random 12-byte IV; 16-byte auth tag appended to ciphertext.
  On-disk layout: `base64(iv || ciphertext || auth_tag)`.
- AWS plaintext: `{ access_key_id, secret_access_key, session_token? }`.
- Azure plaintext: `{ tenant_id, client_id, client_secret }`.
- Redaction hint computed at encrypt time (`AKIA****MPLE` for AWS, partial
  client_id for Azure). Stored alongside ciphertext; surfaced via read
  paths so operators can confirm "yes, right key" without exposing the
  secret.
- `loadCredentialForOrg(repo, orgId, backend)` returns decrypted plaintext
  or null. Unknown `encryption_method` on stored row rejected with
  `invalid_config` so a future KMS-rotation pass can distinguish without
  ambiguity.

**Storage**: migration `0041_cloud_credentials.sql` adds
`cloud_org_credential (id PK, org_id, backend, ciphertext_b64,
encryption_method, redacted_hint, created_at, updated_at)` with unique
index on `(org_id, backend)`. SQLite + Postgres repos.

### Architecture — PASS

- **Network mode is data-on-handle**, not state-in-registry. Backends
  record the mode on the returned handle; downstream callers
  (`getConnectionDescriptor`) read it without round-tripping to storage.
  Recovery paths (handle JSON round-trip) preserve the mode
- **Connection descriptors are pure data**, no I/O. The actual
  tunneling protocol (SSM session-manager, Bastion port forwarding) is
  caller-side concern — a future control-plane connection driver
  consumes these descriptors and dispatches to the right tunnel impl
- **Credentials use Node's built-in `node:crypto`** — no third-party
  crypto deps, no native compilation. AES-256-GCM is FIPS-grade and
  industry standard
- **Module-level key cache** with `resetEncryptionKeyForTests` helper
  matches the budget-gate / reaper singleton patterns from sub-task 5
- **Loader-vs-storage separation**: `CloudCredentialsRepo` holds
  ciphertext; `loadCredentialForOrg` is the decrypter at the call site;
  the AWS/Azure backends do NOT yet auto-consume the loader (deferred
  per the "deferred" section below)

### Product — PASS

- All three modes are operator-visible from both MCP and CLI; the
  trigger phrases agents would use ("provision a VM with no public IP",
  "tunnel through SSM", "use Azure Bastion") map cleanly to the
  `network.mode` schema field
- Connection-descriptor verb gives operators a debuggable view of "how
  WOULD I reach this VM" without having to dial it
- Credentials surface intentionally narrow: set / get / remove. No
  list-all-orgs (deferred); no plaintext echo on get; redaction hints
  visible in human-readable AND JSON output paths
- Fail-loud on missing `SIGNALMAN_CRED_KEY` — operators get an
  immediate clear error rather than a silent insecure default
- Commit messages explicitly document the deferred auto-injection (set
  creds today via CLI/MCP; provisionInstance still uses the SDK default
  chain — wiring is sub-task 6 commit 3 / sub-task 8 scope)

### Security — PASS

- **AES-256-GCM with per-record random IV.** Nonce reuse is
  catastrophic for GCM; rolling fresh randomness per encrypt is the
  safe default. Tested: same plaintext encrypted twice produces
  different ciphertexts
- **Auth tag verification on decrypt.** GCM's built-in MAC catches
  tampering; tested with a 1-bit ciphertext flip
- **Opaque decryption errors.** A failed decrypt throws
  `"failed to decrypt cloud credential"` regardless of cause. The
  underlying crypto error (which could leak length / structure info) is
  swallowed. Different-key decrypt and tampered-ciphertext decrypt both
  surface the same opaque message
- **Plaintext never leaves the encrypter.** MCP `signalman_creds_get`
  returns ONLY the safe fields — id, orgId, backend, redactedHint,
  encryptionMethod, createdAt, updatedAt. The CLI `creds get` output
  is the same shape. Tests assert that plaintext substrings do NOT
  appear in captured stdout
- **Fail-loud on missing key.** No silent fallback to plaintext storage
  if `SIGNALMAN_CRED_KEY` is unset — operators must opt in. Audit
  reasoned out the alternative (silent fallback) as a security trap
- **Stable redaction hint computed at encrypt time** (not on read).
  Reading "just the hint" never decrypts the secret — minimal exposure
  surface
- **Encryption method versioned.** Stored alongside ciphertext so a
  future KMS-rotation pass can identify rows to migrate; an unknown
  method is rejected at load time
- **Network-mode invariant**: `aws_ssm` forces
  `AssociatePublicIpAddress=false` even if the operator's
  `assign_public_ip` field would otherwise enable it. Tested with an
  explicit `assign_public_ip: true` config to confirm the override
- **Sentinel-tag spoofing defence** from sub-task 5 carries forward
  unchanged

# WS6 milestone 7 — WS3 promotion auto-approver health-gate (2026-05-15)

Closes the wave-2 WS3↔WS2 integration gap. A tier-to-tier promotion
policy can declare a `health_gate` in its `gate_config` that defers
auto-promotion until the source-tier deployment has accrued N
consecutive recent health-check passes inside a configurable window.
Works across all target kinds (vm, k8s, cloud_*) because it reads
from the existing `health_check` table — no k8s-specific code path.

## Commit

```
a7c3b84 feat(ws6 m7): WS3 promotion auto-approver health-gate (WS2 readiness)
```

## Schema

Migration `0071_promotion_health_gate.sql`:

```sql
ALTER TABLE approval ADD COLUMN requires_health_gate INTEGER NOT NULL DEFAULT 0;
CREATE INDEX approval_health_gate_idx
  ON approval (requires_health_gate, status)
  WHERE deleted_at IS NULL AND requires_health_gate = 1 AND status = 'pending';
```

Default 0 preserves back-compat. Partial index keeps tick-time scan
cheap regardless of post-deploy approval accumulation.

## Config shape

```jsonc
{
  "gate_config": {
    "health_gate": {
      "min_pass_count": 3,    // last N most-recent checks all 'pass'
      "window_minutes": 30    // newest within this window of now
    }
  }
}
```

## Semantics

| Gate kind | + health_gate | Behaviour |
|---|---|---|
| auto | yes | Listener queues `pending` with `requires_health_gate=1`; tick fires when gate opens. |
| time_delay | yes | AND condition — `auto_approve_at` elapsed AND health gate open. |
| manual | yes | Gate IGNORED. Operator approval is the explicit gate; doesn't need a precondition. |
| any | yes, but `sourceTargetId IS NULL` | Gate IGNORED (initial-tier policy has no source to check). |
| any | no | Original behaviour preserved. |

Operator-driven `signalman_promotion_approve` overrides the gate
unconditionally. A single recent `fail` re-closes the gate (most-
recent N must be uniformly `pass`).

| Concern | Mitigation |
|---|---|
| **Untrusted manifest validation** | Strict-validating parsers (`oci/guards.ts`) reject every malformed field before persistence: mediaType allowlist, sha256-only digest, non-negative *safe* integer size, all-string annotations, platform.architecture+os mandatory non-empty. | **Upload-UUID enumeration** | 128-bit random IDs (`crypto.randomBytes(16).toString("hex")`). `UploadFsStore.pathFor` validates the 32-hex shape before the filesystem touch — defends against `..` traversal, `/`, uppercase, short, non-hex. |
| **Chunked-upload DoS** | Per-route `maxBodyBytes` cap (default 5 GiB). 24-hour persisted TTL per Q8, refreshed on every PATCH. Reaper sweeps SQL row + tmp file as a pair on a 5-minute cadence so neither side leaks. Cross-repo upload smuggling rejected at PATCH time (upload session is bound to its initiating repository). |
| **Manifest signature trust path** | OCI manifests pinned byte-identical via `index.putManifest(manifest, rawBytes, provenance)` — the OCI digest IS the sha256 of the literal bytes the operator pushed; any re-serialization would corrupt the digest. PUT-by-digest verifies path reference matches computed digest (DIGEST_INVALID otherwise). Foreign (`urls`) layers exempt from blob existence per spec. |
| **Image-index child scope** | Index manifests' child digests must resolve in the SAME repository — cross-repo references rejected as MANIFEST_BLOB_UNKNOWN. |
| **Cosign signature trust** | Ed25519 only on both sign and verify. Verifier re-hashes the payload blob and refuses on storage corruption. Manifest-digest binding inside the payload prevents signature replay across different manifests. Optional `expectedDockerReference` defends against the same signature being passed off as covering a different repo. |
| **Catalog tenant-leak** | `/v2/_catalog` scoped to `oci/%` storage names — cargo + npm namespaces don't bleed in. Per-tenant catalog scoping is RBAC work, deferred to v0.2.1; documented as a known limitation. |
| **JWT replay** | 1-hour TTL (Docker Distribution default). `exp` + `iat` enforced with 60s clock-skew tolerance. Algorithm allowlist (`EdDSA` only) defends against `none` / `HS256` confusion. Audience + issuer pinning rejects cross-realm tokens. |
| **Upstream digest integrity** | When the upstream advertises `Docker-Content-Digest`, the registry re-computes sha256 of the body and refuses on mismatch (audit `phase=digest_mismatch`). Blob proxy fetcher refuses bytes whose sha256 ≠ requested digest. |
| **SigV4 signing-key derivation** | HMAC chain `date → region → service → aws4_request` per spec. Session tokens are signed-headers-included so STS-issued requests can't be replayed without their amz-security-token. |
| **AWS credential handling** | Read from explicit options first, env vars second. Fail-closed when credentials are absent. Never logged. |
| **SQL parameterization** | Every new SQL statement uses `db.prepare(...)` with bound `?` placeholders. No string interpolation. |
| **Path-traversal-safe last cursor on tags/list** | Validated against the OCI tag grammar before being passed to SQL. |
| **Fallback when no challenge realm is configured** | `/v2/` issues 401 *without* `WWW-Authenticate` so Docker CLI clients understand to fall back to direct `sk_` bearer instead of looping on the missing token endpoint. |

### Architecture — PASS

- **Reaper**: backend-agnostic via tag inspection on `CloudInstanceHandle.tags`; no per-vendor coupling in `reaper.ts`. The handle's new `tags?` field is **optional** + **informational** so back-compat is preserved (no caller breaks; existing handles with no tag = "no TTL" = skipped)
- **Budget gate**: clean storage / business-logic separation. `CloudBudgetGate` takes injectable `CloudBudgetRepo` + `CloudUsageRepo` — tests substitute in-memory SQLite; production wires through `ControlPlane.cloudBudgets / cloudUsage`
- **Module-level singletons** (`getOrCreateReaper`, `setBudgetGate / getBudgetGate`) — chosen over constructor injection on AWS/Azure backends because (a) the registry pattern requires no-arg factories, (b) tests can wire/clear the singleton per case via `reset*ForTests` helpers
- **Cost table is a static const + lookup function**; no DI, no API call, no network dependency on the hot path. Design §13.5 acknowledges this as "naive at first"; real pricing API is documented v0.3.x followup
- **Migration block 0040–0049** reserved for this sub-task per `docs/workstreams/PLAN.md`. Used `0040_cloud_budgets.sql` only; 0041–0049 free for sub-tasks 6–8

### Product — PASS

- Both MCP and CLI surfaces shipped per the user's "expose new capabilities via MCP and CLI" directive
- MCP tools have natural-language descriptions agents can reason over (trigger phrases for "force a reaper sweep", "show me the org's budget", "what would this stack cost")
- CLI verbs use `--format json` for scripting and human-readable output by default; exit codes mapped to existing project conventions (0 success, 4 backend error)
- Operator-facing guardrails baked into commit messages + module headers: idempotent terminate / destroy, absent-tag = no-TTL = skip (back-compat), unknown-SKU fallback rate is high (over-protect not under-protect)
- "Naive estimate" is honest in operator-facing output: CLI footer reads "Estimates use a static SKU × region table from v0.3.0-5; treat as guardrail, not invoice."
- SKILL.md updates batched for a followup commit (per the sub-task 8 plan in PLAN.md) — operators can already use the verbs/tools directly; agent-discovery via skill files lands with the rest of the sub-task 8 surface

### Security — PASS

- **Sentinel-tag spoofing defence** carried forward: caller `tags` cannot override `signalman-managed`, `signalman-org`, `signalman-ttl-minutes`, or the new `signalman-ttl-expires-at`. AWS + Azure backends filter them in `buildInstanceTags` / `buildAzureTags`
- **Reaper malformed-tag guardrail**: a corrupt `signalman-ttl-expires-at` value (non-numeric, negative, NaN) is treated like absent — skipped + logged with structured stderr. Explicit protection against a single bad tag triggering a sweep-mass-terminate. Test coverage exists for all 4 corruption shapes
- **Budget gate runs before any vendor API call**: `gate.checkForConfig(config)` throws on over-budget BEFORE EC2 / Azure SDK invocation. No way for an over-budget caller to land an instance even momentarily
- **Storage layer uses parametrised queries throughout**: both SQLite and Postgres repos use `?` / `$N` placeholders, never string concatenation, for org_id and instance_id. No SQL injection surface
- **Best-effort usage records** intentionally swallow storage errors after successful provision — but **only after** the budget check has passed. Failing to record usage cannot result in over-budget provision (because the check happens first)
- **Cost table is read-only** (`Object.freeze`); operator-side runtime mutation impossible
- **No credentials handled** in this sub-task — all credential code paths already existed in sub-tasks 2/3 and remain unchanged
- **CLI commands honour `SIGNALMAN_DATA_DIR`** for storage isolation (tests use this for per-case sandboxing); no hardcoded paths

# v0.3.0-1 — Record / Replay (design note)

**Status**: in progress on `feat/v0.3.0-record-replay`, branched off
v0.3.0-4 since the plugin already exposes the run/status surfaces
this epic extends.

---

## 1. Problem

The host TS surface for record/replay is already mostly built:

- `host/src/verbs/record.ts` — 652 LOC, 89% coverage. Implements
  `runRecord` (start a recording session), `runRecordFinalize`
  (synthesize candidate scenario + promote), and `recordMcpCall`
  (append-only call capture with redaction).
- `host/src/server.ts` — every MCP tool dispatched through
  `withRecording(tool, params, fn)`, which captures the call to the
  active recording session's `calls.jsonl`.
- CLI: `signalman record <name>` + `signalman record finalize <id>`.
- MCP: `signalman_record` + `signalman_record_finalize`.

But the **Loom plugin** ships a stub:

- `loom.signalman.record` description says "[v0.2.0 stub] Returns
  not-implemented in v0.1.0" — misleading; the underlying CLI is
  fully functional.
- `record_output` schema is `{status, message}` — doesn't reflect
  the real `RecordResult` shape (`recording_id`, paths, timestamps).
- `loom.signalman.record_finalize` doesn't exist as a plugin tool
  at all. Operators going through Loom can start a recording but
  must drop to direct CLI to finalize it.

v0.3.0-1 closes the plugin gap so Loom-fronted agents have a
complete record-then-promote workflow:

1. Agent: `loom.signalman.record { name }` → returns recording_id.
2. Agent invokes a sequence of `loom.signalman.run` / `list` /
   `describe` / `plan` etc; the host's `withRecording` captures
   each into `calls.jsonl`.
3. Agent: `loom.signalman.record_finalize { recording_id }` →
   synthesizes `.signalman/scenarios/<scenario_id>/` and returns
   the promoted paths.
4. Operator reviews + commits.

## 2. What ships in this epic

### 2.1 Plugin `record_output` schema graduates

Replace `{ status, message }` with the real `RecordResult` shape:

```json
{
  "status": "recording",
  "recording_id": "rec_2026-05-13T20-00-00-000Z_a1b2c3",
  "name": "my-flow",
  "safe_name": "my-flow",
  "started_at": "2026-05-13T20:00:00Z",
  "expires_at": "2026-05-13T20:10:00Z",
  "duration_seconds": 600,
  "recording_path": "<abs>",
  "state_path": "<abs>",
  "calls_path": "<abs>",
  "message": "Recording session started..."
}
```

Tool description updated to drop "[v0.2.0 stub]" framing.

### 2.2 New plugin tool: `loom.signalman.record_finalize`

Shells out to `signalman record finalize` and passes the
`RecordFinalizeResult` back unmodified. Input shape:

```json
{
  "recording_id": "rec_...",          // OR
  "recording_path": "<abs path>",
  "scenario_id": "smoke/my-flow",     // optional override
  "force": false                       // optional, overwrite existing
}
```

Output shape:

```json
{
  "status": "finalized",
  "recording_id": "rec_...",
  "scenario_id": "smoke/my-flow",
  "scenario_path": "<abs>",
  "setup_path": "<abs>",
  "workflow_path": "<abs>",
  "assertions_path": "<abs>",
  "captured_call_count": 12,
  "emitted_tool_blocks": 9,
  "skipped_call_count": 3,
  "malformed_line_count": 0
}
```

### 2.3 README workflow documentation

A "Record / Replay (v0.3.0+)" subsection under Scenario Format
describing the four-step workflow + the promotion review checklist
(VM placeholders, selectors, waits, assertions).

## 3. Out of scope (deferred)

- **Synthesis quality improvements**: the current synthesizer emits
  a `recorded-vm` placeholder and tool blocks but doesn't infer
  template, network class, or assertions. Improvements (template
  inference from `signalman list`, assertion inference from
  observed pass/fail) are tracked as v0.3.0-1 follow-ups.
- **CLI capture for direct invocations**: the `withRecording`
  wrapper only fires on MCP tool calls. Direct CLI invocations
  (`signalman run scenario`) aren't captured. That's tracked as a
  v0.3.0-1 follow-up; the natural place to hook is the CLI verb
  dispatcher in `cli.ts`.
- **Recording UI in Loom TUI**: a TUI command for "start recording,
  do some agent work, stop and finalize" is Loom-side work.

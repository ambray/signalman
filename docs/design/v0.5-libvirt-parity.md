# v0.5 libvirt parity

**Status:** design proposal (2026-05-16). No code shipped yet.
**Owner:** WS11 (`docs/workstreams/prompts/ws11-vmrun-vmware-convergence.md` — note: the prompt's filename predates the 2026-05-16 redirect; rename or rewrite when scope is locked).
**Predecessor:** v0.4.0-4 chunk 2 shipped `LibvirtBackend` (`host/src/hypervisors/libvirt.ts`) as the cross-platform completion of WS4. The backend registers + selects cleanly and the parser / argv unit lanes pass — but several methods are placeholder-grade and would not survive contact with a real KVM host.

## Problem statement

Today (v0.4.x) `LibvirtBackend` is wired into `selector.ts`, picked first on Linux hosts, and covered by unit tests with injected `virsh` execs. But:

| Symptom | What it looks like today |
|---|---|
| `executeCommand` returns `exitCode: 0` always. | Backend submits `guest-exec` to qemu-guest-agent (QGA), gets `{"return":{"pid":N}}`, returns that as `stdout` with `exitCode: 0` hardcoded. Never polls `guest-exec-status`. Scenarios that gate on exit code silently pass. |
| `copyFileToVM` / `copyFileFromVM` fail against real QGA. | `buildGuestFilePayload` emits `guest-file-open-write` / `guest-file-open-read` — neither is a real QGA command. The actual API is three RPCs: `guest-file-open` → `guest-file-write`/`read` → `guest-file-close`, with base64 buffers. |
| `getStatus.guestAgentReachable` hardcoded `false`. | Orchestrator's parallel guest-readiness wait (`scenarios/orchestrator.ts`) never succeeds on libvirt. |
| `createVM` throws `unsupported_operation`. | `provisioning/provision.ts` and `provisioning/ephemeral-vm.ts` call `backend.createVM` — both unusable on libvirt today. |
| `domifaddr` defaults to `--source lease`. | VMs on bridges or with static IPs return no address even when QGA could answer via `--source agent`. |
| No `setVmMemory` / `setVmProcessor` / `waitForHeartbeat`. | Hyper-V implements all three optional methods on `HypervisorBackend`. Libvirt implements none. Hosts that depend on these (memory / CPU reshape between scenarios, heartbeat readiness wait) can't switch to libvirt. |

v0.5 closes the gap. The selector is unchanged; existing config keeps working. The implementation modernizes to match Hyper-V's contract surface.

## Goals

1. **Parity with `HypervisorBackend` contract.** Every method on the interface — including optional `waitForHeartbeat` / `setVmMemory` / `setVmProcessor` — has a working libvirt implementation.
2. **End-to-end demo against the operator's local KVM.** Provision a real Ubuntu VM via `signalman vm provision`, exec a command, copy a file, snapshot, destroy. Result captured in `.workstream-status.md`.
3. **Coverage holds.** ≥80% lines / ≥70% branches across `host/src/hypervisors/libvirt.ts`. Unit + argv + system-lane tests.
4. **No behavior change for non-libvirt operators.** Selector, config, and `signalman vm` CLI surface are unchanged; libvirt is only picked when probed available or explicitly selected.

## Non-goals

- **Native libvirt-node bindings.** Subprocess-via-`virsh` continues to be the pattern. Locked in `libvirt.ts` §"Why virsh, not libvirt-node" — re-litigation costs more than the gain.
- **PCI / GPU passthrough configuration.** Out of scope; XML builder produces a flat `virtio` baseline.
- **Live migration.** Out of scope.
- **vSphere / ESXi.** That's the VMware track. Libvirt is local KVM only here.
- **A full libvirt-XML schema.** The createVM builder produces a minimal, opinionated XML — enough to provision a signalman-managed VM. Operators with bespoke topology continue to `virsh define` their own.

## Locked design

**Confirmed by operator 2026-05-16:**

1. **Scope = libvirt parity with hyper-v's contract surface.** Four bug-class fixes (executeCommand exit code, QGA file copy, guestAgentReachable, domifaddr fallback) plus the three optional interface methods (`setVmMemory`, `setVmProcessor`, `waitForHeartbeat`) plus a minimal `createVM` XML builder.
2. **Subprocess pattern preserved.** All work goes through the existing `LibvirtExec` injectable + the `virsh` CLI. No native dependency added.
3. **Branch name: `feat/v0.5-libvirt-parity`** (cut from main 2026-05-16).
4. **Guest image for end-to-end demo: Ubuntu cloud-image** (jammy or noble qcow2), cloud-init seed ISO installs `qemu-guest-agent`. Cached after first run.
5. **System test against `test:///default`** (libvirt's deterministic in-memory driver) joins the test suite as the first real-virsh-binary test. Skipped when `process.platform !== "linux"` or `SIGNALMAN_LIBVIRT_TESTS !== "1"`.

## Conformance matrix

Method-by-method delta from Hyper-V (canonical) to libvirt-today to libvirt-target:

| Method | Hyper-V (`hyperv.ts`) | libvirt today | libvirt target |
|---|---|---|---|
| `isAvailable` | `Get-VMService` smoke | `virsh version --daemon` exit 0 | unchanged |
| `createVM` | `New-VM` + `Set-VMProcessor` | throws `unsupported_operation` | **new** — build domain XML from `VMConfig`, `virsh define`, return handle |
| `startVM` | `Start-VM -AsJob` + idempotent | `virsh start`, idempotent on "already active" | unchanged |
| `stopVM` | `Stop-VM -AsJob` (force/graceful) | `virsh shutdown` / `destroy`, idempotent on "not running" | unchanged |
| `pauseVM` | `Suspend-VM` | `virsh suspend` | unchanged |
| `resumeVM` | `Resume-VM` | `virsh resume` | unchanged |
| `deleteVM` | `Stop-VM -TurnOff` + `Remove-VM -Force` | `virsh destroy` (best-effort) + `undefine --remove-all-storage` | unchanged |
| `getStatus` | `Get-VM` (State / Uptime / Memory / IP) | `domstate` + `domifaddr` (lease only); `guestAgentReachable: false` | **fix** — `guestAgentReachable` via `guest-ping`; `domifaddr` falls back `lease → agent → arp` |
| `listVMs` | `Get-VM` | `virsh list --all --name` | unchanged |
| `createCheckpoint` | `Checkpoint-VM` | `snapshot-create-as` | unchanged |
| `restoreCheckpoint` | `Restore-VMSnapshot` | `snapshot-revert` | unchanged |
| `deleteCheckpoint` | `Remove-VMSnapshot` | `snapshot-delete` | unchanged |
| `listCheckpoints` | `Get-VMSnapshot` | `snapshot-list` | unchanged |
| `copyFileToVM` | `Copy-VMFile -FileSource Host` | broken — `guest-file-open-write` is not a real QGA verb | **fix** — `guest-file-open(mode=w)` → chunked `guest-file-write(handle, buf-b64)` → `guest-file-close(handle)` |
| `copyFileFromVM` | `Copy-Item -FromSession` over PS Direct | broken — `guest-file-open-read` is not a real QGA verb | **fix** — `guest-file-open(mode=r)` → chunked `guest-file-read(handle, count)` (base64 decode) → `guest-file-close(handle)` |
| `executeCommand` | `Invoke-Command -VMName … -ScriptBlock` | submit-only via `guest-exec`; `exitCode: 0` hardcoded; stdout is the JSON envelope | **fix** — `guest-exec` to submit, poll `guest-exec-status` until `exited: true`, base64-decode `out-data` / `err-data`, return real `{exitCode, stdout, stderr}` |
| `getVmIpAddress` *(opt.)* | `Get-VMNetworkAdapter`.IPAddresses | `domifaddr` (lease only) | **fix** — `lease → agent → arp` fallback chain (shared helper with `getStatus`) |
| `waitForHeartbeat` *(opt.)* | CIM event subscription on `Msvm_ComputerSystem` | **missing** | **new** — `guest-ping` poll with exponential backoff (capped) until deadline |
| `setVmMemory` *(opt.)* | `Set-VMMemory -StartupBytes <N>MB` | **missing** | **new** — `virsh setmaxmem` (if growing past max) + `virsh setmem` |
| `setVmProcessor` *(opt.)* | `Set-VMProcessor -Count N` | **missing** | **new** — `virsh setvcpus --config --maximum N` + `virsh setvcpus --config N` |

## createVM XML shape

Minimal opinionated domain XML, produced by an internal `buildDomainXml(config: VMConfig)` function:

```xml
<domain type='kvm'>
  <name>{{config.name}}</name>
  <memory unit='MiB'>{{config.memoryMB ?? 2048}}</memory>
  <vcpu placement='static'>{{config.cpus ?? 2}}</vcpu>
  <os>
    <type arch='x86_64' machine='q35'>hvm</type>
    <boot dev='hd'/>
  </os>
  <features><acpi/><apic/></features>
  <cpu mode='host-passthrough'/>
  <devices>
    <emulator>/usr/bin/qemu-system-x86_64</emulator>
    <disk type='file' device='disk'>
      <driver name='qemu' type='qcow2'/>
      <source file='{{diskPath}}'/>
      <target dev='vda' bus='virtio'/>
    </disk>
    <interface type='network'>
      <source network='{{config.network?.switchName ?? "default"}}'/>
      <model type='virtio'/>
    </interface>
    <channel type='unix'>
      <source mode='bind'/>
      <target type='virtio' name='org.qemu.guest_agent.0'/>
    </channel>
    <console type='pty'/>
  </devices>
</domain>
```

`diskPath` is derived from `config.template`:
- If `config.template` is an absolute path to an existing qcow2 → use a qcow2 backing-file disk image (`qemu-img create -f qcow2 -F qcow2 -b <template> <new>.qcow2`) so the template is preserved.
- If `config.template` is unset → caller must pre-stage the disk; createVM fails with `invalid_argument`.

Storage location is the libvirt `default` pool's target dir (typically `/var/lib/libvirt/images/`), looked up via `virsh pool-dumpxml default`. If the pool doesn't exist, fail with `invalid_argument` and an actionable error message ("run `virsh pool-define-as default dir --target …`").

The QGA channel is the critical addition: without it `executeCommand` / `copyFile*` are blind.

## QGA payload shapes

For reference (these are what M1 / M2 implement). The backend never embeds shell metacharacters in these payloads — JSON serialization handles quoting.

**executeCommand (M1):**
```jsonc
// submit
{"execute":"guest-exec","arguments":{"path":"/bin/echo","arg":["hi"],"capture-output":true}}
// → {"return":{"pid":1234}}

// poll (exponential backoff, capped at ~1s; deadline = caller's timeoutMs)
{"execute":"guest-exec-status","arguments":{"pid":1234}}
// → {"return":{"exited":true,"exitcode":0,"out-data":"aGkK","err-data":""}}
```

**copyFileToVM (M2):**
```jsonc
{"execute":"guest-file-open","arguments":{"path":"/dest","mode":"w"}}  // → {"return":<handle>}
// chunked, up to ~48KiB per chunk to keep base64 under QGA's transfer cap
{"execute":"guest-file-write","arguments":{"handle":<handle>,"buf-b64":"…"}}
// repeat until EOF
{"execute":"guest-file-close","arguments":{"handle":<handle>}}
```

**copyFileFromVM (M2):**
```jsonc
{"execute":"guest-file-open","arguments":{"path":"/src","mode":"r"}}
{"execute":"guest-file-read","arguments":{"handle":<handle>,"count":<bytes>}}
// → {"return":{"count":N,"buf-b64":"…","eof":false}}
// loop until eof
{"execute":"guest-file-close","arguments":{"handle":<handle>}}
```

**guestAgentReachable (M3):**
```jsonc
{"execute":"guest-ping"}  // → {"return":{}}
```

1. `npm test` from `host/` is green.
2. `npx tsc --noEmit` clean.
3. Coverage holds: ≥80% lines / ≥70% branches across `libvirt.ts`.
4. System-lane test (M6) passes on this Linux host with `SIGNALMAN_LIBVIRT_TESTS=1`.
5. M7 end-to-end demo log is captured in `.workstream-status.md` under "## Manual end-to-end test log".
6. No regression on the existing Hyper-V / Tart / VMware / vmrun / service backends — all selector tests stay green.
7. 4-lens audit in `.workstream-status.md`. Security lens: argv composition still goes through `sanitizeVmName` / `sanitizeLabel` / `sanitizePath`, no new injection surface.

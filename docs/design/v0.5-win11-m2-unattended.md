# v0.5 Win11 M2 — Unattended.xml first-boot injection

**Status:** detail design (2026-05-17).
**Owner:** continuation of WS-win11-deploy.
**Branch:** `feat/v0.5-win11-deploy` (continues after M1 ff-merged to main `33cd845`).
**Predecessor:** M1 (`86f41ea`) — `signalman vm bootstrap-win11` verb + 12-step pipeline + state journal already shipped.
**M0 Q4 lock (M1 commit `87e57c9`):** Unattended.xml-driven first-boot — the alternative "boot-config-poller" was rejected as the strongly-discouraged option in the design.

This doc is M2's M0 equivalent: it locks the sub-design + decomposes M2 into 5 stories, each with its own 80%-coverage gate. The cross-milestone 4-lens audit closes the milestone.

---

## Problem statement

After M1, `signalman vm bootstrap-win11 <name>` produces an
`agent-installed`-checkpointed VM. But step 5 (boot, wait for
heartbeat) requires the operator to manually walk through Win11's
first-boot OOBE: region, EULA, local-account creation, privacy
prompts. The verb is not actually unattended.

M2 closes that gap by injecting an Unattended.xml during VM
creation. Sysprep on the template runs the unattended pass on
first boot: OOBE skipped, local-admin auto-created with the
scenario-supplied credentials, RDP enabled, auto-logon counted
down so subsequent steps (testsigning, MSI install) run against
an already-logged-in desktop.

End state: the M1 pipeline becomes truly hands-off. An operator
runs `bootstrap-win11 demo` against a fresh template and gets an
agent-installed checkpoint in ~10 minutes without touching the
guest UI.

---

## Goals

1. **Unattended.xml composer.** Deterministic XML emitted from a
   strongly-typed `UnattendedConfig` input. Round-trips clean
   through parse + re-emit. Microsoft schema compliance (UTF-8
   with BOM; SystemDrive context; per-pass FirstLogonCommands).
2. **CIDATA seed ISO writer.** Writes a small ISO9660 volume
   labelled `CIDATA` containing `Autounattend.xml` (Windows
   looks for this name on removable media at first boot). Pure
   TypeScript — no shell-out to `mkisofs`/`genisoimage`/`oscdimg`,
   so the pipeline works on hosts without Windows ADK or Linux
   `cdrtools` installed.
3. **Hyper-V `extraCdroms` parity with libvirt.** libvirt-polish
   PL5 shipped `VMConfig.extraCdroms?: string[]`; M2 wires it
   into the Hyper-V backend (Add-VMDvdDrive + Set-VMFirmware
   boot order). Selector-agnostic so the same bootstrap pipeline
   works on both backends.
4. **Bootstrap pipeline step 2.5.** Inserts seed-ISO compose +
   attach between "read or set firmware" (step 4) and "boot" (5).
   Cleanup (detach + delete seed ISO) lands after step 12
   (checkpoint), or on `--cleanup-on-failure`.
5. **80% coverage on every new file.** Lines AND branches.
6. **4-lens audit at M2 closure.** Product lens emphasis (Q4
   answer + locked design 2 implication: does the operator
   experience handle a Win11 first-boot without pop-ups?).

---

## Non-goals

- **Domain join.** Bootstrap is for standalone Win11 VMs. Domain
  join lives in a separate Sysprep `<Component name="Microsoft-
  Windows-UnattendedJoin">` block; not in scope.
- **Multi-locale support.** Locale is operator-supplied
  (`--locale en-US`); we emit it verbatim. Localised OEM messages
  / EULA paths are not configured.
- **OEM branding.** No `<OEMInformation>` block.
- **Static IP / DNS overrides via unattended.** Network config
  comes from the scenario / hypervisor, not Unattended.xml.
- **Pre-OOBE driver staging.** If the operator needs
  `$WinPEDriver$\` injection, they pre-stage on the VHDX.
- **Microsoft Account / Entra-ID join.** Local accounts only.
- **Server SKUs.** Same Win11-workstation scope as M1.

## Locked design

Inferred from M1's pipeline shape + Microsoft's
WAIK / Sysprep documentation + `b0ec24c`'s scenario-creds
plumbing. Confirm at M0-equivalent gate; the agent locks defaults
unless code review surfaces a contradiction.

1. **Seed ISO label = `CIDATA`.** Windows sysprep searches all
   removable media for `Autounattend.xml` at root; the conventional
   label is `CIDATA` (matches cloud-init's volume name; Windows
   doesn't care about the label, only the file name). Picking a
   consistent label simplifies the cleanup detach step.
2. **Seed-ISO filename: `Autounattend.xml`** (Microsoft spec).
3. **Encoding: UTF-8 with BOM.** Required by Microsoft processor.
4. **One unattended pass: `specialize` + `oobeSystem`.** We do not
   touch `windowsPE` (the template is already-installed; no
   imaging-time config needed).
5. **`oobeSystem` block:**
   - `OOBE/HideEULAPage = true`
   - `OOBE/HideLocalAccountScreen = true`
   - `OOBE/HideOnlineAccountScreens = true`
   - `OOBE/HideWirelessSetupInOOBE = true`
   - `OOBE/ProtectYourPC = 3` (skip the optional services pitch)
   - `UserAccounts/LocalAccounts/LocalAccount` with the
     scenario-supplied admin credentials.
   - `AutoLogon/Enabled = true` with `LogonCount = N`
     (configurable; default 3 — enough for testsigning reboot
     cycle).
   - `FirstLogonCommands` with one entry: a no-op `cmd.exe /c
     ver` so the unattended pass has a synchronous gate before
     the desktop appears (gives the host's heartbeat-waiter a
     deterministic signal).
6. **`specialize` block:**
   - `ComputerName = <vmName>` (truncated + transliterated to
     NetBIOS-15-char-friendly form).
   - `TimeZone` (operator-supplied; default `UTC`).
   - `RegisteredOwner = signalman`, `RegisteredOrganization = signalman`.
   - RDP enable via `Microsoft-Windows-TerminalServices-LocalSessionManager`
     `fDenyTSConnections = false` + firewall via
     `Microsoft-Windows-TerminalServices-RDP-WinStationExtensions`.
7. **Seed-ISO bytes assembled as ISO9660 Level 1 with Joliet
   extension.** Joliet supports long filenames; we use mixed-case
   `Autounattend.xml` so Windows finds it.
8. **Seed ISO stored at `.signalman/state/bootstrap-win11/
   <vm-name>.seed.iso`.** Same directory as the state journal.
   Cleaned up by step 12 (checkpoint) — seed media is detached
   + deleted before the checkpoint is taken so the checkpoint
   doesn't pin a stale ISO blob.
9. **Hyper-V `extraCdroms` impl: PowerShell `Add-VMDvdDrive`** with
   the ISO path. Boot order via `Set-VMFirmware -BootOrder` only
   if the existing primary boot device is the HDD (default — no
   reorder needed for a typical template).
10. **State journal extension.** `BootstrapWin11State` gains
    `seedIsoPath: string | null` + `seedIsoAttached: boolean` so
    cleanup is correct on resume after partial failure.
11. **Cleanup on failure.** When `--cleanup-on-failure`, detach
    + delete seed ISO before VM removal. Without that flag,
    leave seed ISO in place for operator inspection.
12. **Idempotency.** Re-running bootstrap on a VM whose state
    journal says `seedIsoAttached: true` is a no-op (the existing
    M1 idempotency contract extends naturally).

## Open decisions (M0 gate — auto-lock defaults)

The operator authorised the agent to lock defaults unless code
review surfaces a contradiction. Procedure: open this doc, append
`**Locked 2026-05-17:** <default>` inline under each open Q, then
commit `docs(v0.5-win11-deploy): lock M2 defaults`.

1. **Q1 — ISO builder dependency.** Pure-TS ISO9660 writer
   (~600 lines, no deps) OR shell-out to `mkisofs`/`oscdimg`
   when available? **Default rec:** pure-TS — keeps the
   pipeline dep-free, no host-tool detection branch.
   **Locked 2026-05-17:** pure-TS ISO9660 writer (no host-tool dependency).
2. **Q2 — `AutoLogon.LogonCount`.** Default 3 (covers
   testsigning reboot + a margin) vs Microsoft's default 1?
   **Default rec:** 3.
   **Locked 2026-05-17:** 3 (configurable via `--auto-logon-count`).
3. **Q3 — `ProtectYourPC = 1 | 3`.** 1 = recommended settings,
   3 = no recommended services pitch. **Default rec:** 3.
   **Locked 2026-05-17:** 3 (skip recommended-services pitch).
4. **Q4 — RDP enabled on the bootstrap VM.** True (so an
   operator can RDP in to debug) or false (security default)?
   **Default rec:** true — this is a test/demo VM.
   **Locked 2026-05-17:** RDP enabled by default on bootstrap VMs (this is a test/demo VM).
5. **Q5 — `FirstLogonCommands` hook for heartbeat signal.**
   `cmd.exe /c ver` (no-op) vs `cmd.exe /c "echo ready >
   C:\signalman-ready.txt"` (writes a sentinel the heartbeat
   waiter can stat)? **Default rec:** sentinel file — gives the
   host a real reachable signal beyond QGA-not-installed-yet
   conditions.
   **Locked 2026-05-17:** sentinel file `C:\signalman-ready.txt` via `cmd.exe /c "echo ready > C:\signalman-ready.txt"`.
6. **Q6 — ComputerName transliteration.** Strict NetBIOS-15
   ASCII (truncate + replace non-alphanumeric with `-`) vs
   reject names that don't fit? **Default rec:** transliterate
   silently; log the source vs result if they differ.
   **Locked 2026-05-17:** transliterate silently (truncate + replace non-alphanumeric with `-`); log when source != result.
7. **Q7 — Multiple-CDROM ordering on Hyper-V.** If the template
   already has a DVD drive (Windows install media), where does
   the seed ISO go? **Default rec:** add as a second DVD
   drive (`-ControllerNumber 0 -ControllerLocation N+1`),
   leave the existing one alone. Sysprep scans all removable
   media.
   **Locked 2026-05-17:** add as additional DVD drive (`Add-VMDvdDrive`) without reordering or replacing existing media.
8. **Q8 — TimeZone format.** Microsoft uses
   "Pacific Standard Time" (display-name form), not IANA
   ("America/Los_Angeles"). **Default rec:** accept IANA on
   the CLI, ship a small static lookup table for the ~30
   common zones, error explicitly when an unmapped IANA name
   appears.
   **Locked 2026-05-17:** accept IANA + Microsoft display-name forms on the CLI; static lookup table for ~30 common zones; explicit error on unmapped IANA name.

## Risks + mitigations

| Risk | Mitigation |
|---|---|
| Pure-TS ISO9660 writer subtly wrong → Win11 refuses to mount seed | Story 2's tests include byte-level inspection of Volume Descriptor + Path Table; gated system-lane test mounts the ISO on a real Win11 VM and verifies sysprep consumed it |
| `AutoLogon` count exhausted before reboot cycle finishes | Default 3 covers testsigning reboot + MSI install + checkpoint; configurable upward via `--auto-logon-count` for operators with longer flows |
| Different Win11 template builds (22H2 vs 23H2) interpret Unattended.xml differently | Pin demo template to 23H2 in the M1 audit doc + this M2 doc; document as known constraint |
| `FirstLogonCommands` sentinel race (file written but disk not flushed) | Use `cmd.exe /c "echo ready > C:\signalman-ready.txt && sync"` — or fall back to a 2s sleep + retry on heartbeat waiter |
| Operator password contains XML-special chars | `composeAutounattendXml` entity-encodes the password; covered by unit test |
| Multi-locale UI prompts not suppressed | M2 ships en-US default + a documented `--locale` flag; non-en-US is operator's risk |

## Why this workstream exists

The v0.6 KVM provisioning workstream surfaced direct evidence that signalman's Linux host story is operator-hostile because of recurring sudo gates:

| Required sudo op | Reason | Integrity impact |
|---|---|---|
| `chmod a+r /var/lib/libvirt/images/<file>.qcow2` | Pull setupact.log from a partially-installed VM's qcow2 | None lasting (one-off file mode) |
| `apt install -y libguestfs-tools` | Read NTFS partitions from the host without booting the VM | None — adds a package |
| `chmod 644 /boot/vmlinuz-*` | libguestfs supermin needs to read the kernel image | **Real degradation** — kernel image is mode 600 deliberately on modern distros to block KASLR-bypass reads by unprivileged processes |
| `rm /var/lib/libvirt/images/<file>.qcow2` | Cleanup after a failed install | None lasting |
| `modprobe nbd` | qemu-nbd needs the kernel module loaded | Loads a module |
| `mount -t ntfs-3g ...` | Read NTFS partition without booting | One-off mount |
| `virsh net-define default` | Set up the libvirt default network when absent | Persistent (but bootstrap-time only) |

Asking operators to run these manually:

- **Doesn't scale** to other hosts (the operator running our pipeline on a fresh laptop has to debug each gate independently).
- **Doesn't compose** with autonomous agent operations — every sudo prompt blocks the agent.
- **Weakens host integrity** when the workaround is a permanent permission change (the `vmlinuz` chmod is the clearest example; it persists across reboots and reverses a deliberate security hardening).

The fix is a privileged daemon that signalman talks to via a local Unix socket. Same architectural shape as the existing Windows service (`service/`): the host process stays unprivileged; the service has the privilege. Operations are issued through a narrow, allowlisted API. Audit-logged. Update-distributable via signed packages.

This wave builds that daemon for Linux + the supporting host-bootstrap workflow.

## What success looks like

After Wave C closes:

- Fresh Linux host runs `signalman host bootstrap` once → daemon installed via signed package, systemd unit running, user added to required groups, host-deps.yaml manifest applied. Operator never types `sudo` for the host-side ops signalman needs.
- `signalman host status` — diff current host state against `host-deps.yaml`; report missing deps + actionable remediation.
- Future operations (libvirt pool create, vmlinuz read for libguestfs, NTFS mount, package install) route through the daemon, audit-logged, allowlisted.
- The daemon is job-shaped from day one (Wave B compatibility): long-running ops (apt install, libguestfs operations) are jobs; fast ops (chmod a permitted path, modprobe a permitted module) are request-response.
- All operator-visible permission relaxations on the host are revertible. The daemon does temporary unlocks for specific operations and re-locks afterward (e.g. read the qcow2 with elevated read; the qcow2 stays root-owned).

## Locked decisions

The operator authorized these defaults at workstream design time (2026-05-18). Agent locks them inline in the design doc + proceeds.

1. **Daemon name:** `signalman-privhelper`. Single binary, Rust.
2. **Transport:** Unix socket at `/run/signalman-privhelper.sock` (system-wide installation) OR `/run/user/<uid>/signalman-privhelper.sock` (per-user). Default = system-wide (matches Windows service's system-wide install). Per-user is a v0.7.1 stretch.
3. **Authentication:** `SO_PEERCRED`. The socket file is mode 660 owned by `root:signalman` (a new group; users in this group can talk to the daemon). The daemon checks peer credentials at each connection + refuses connections from outside the group.
4. **Protocol:** length-prefixed JSON over the socket. NOT gRPC — gRPC adds protobuf + Tonic dependency surface that's wasteful for a local socket. Wave B's `JobSpec`/`JobStatus`/`JobEvent` types are serialized as JSON directly.
5. **Op API:** narrow + allowlisted + compile-time-fixed. Every op is a discriminated-union variant with typed args. No `exec_arbitrary_command`. Standard set:
   - `ensure_pkgs(pkgs: Vec<String>)` — `pkgs` allowlist baked in at build time (libguestfs-tools, swtpm, ovmf, qemu-utils, qemu-kvm, libvirt-clients, libvirt-daemon-system, ntfs-3g). Adding a new package = code change + recompile + re-review.
   - `kernel_make_readable_oneshot()` — flips `/boot/vmlinuz-$(uname -r)` to mode 644 + records original mode + schedules a re-lock-on-disconnect (when the last libguestfs op finishes).
   - `qcow2_chmod_readable(path: AbsPath)` — path must match `/var/lib/libvirt/images/*.qcow2`.
   - `qcow2_delete(path: AbsPath)` — same path allowlist.
   - `libvirt_pool_create(name: String, path: AbsPath)` — path must be under `/var/lib/libvirt/` or `$HOME/libvirt-images/`.
   - `libvirt_pool_delete(name: String)`.
   - `libvirt_network_define_default()` — defines the stock `default` network if absent.
   - `nbd_module_load()` — `modprobe nbd`. Idempotent.
   - `nbd_connect(qcow2: AbsPath)` → `NbdDev`.
   - `nbd_disconnect(dev: NbdDev)`.
   - `mount_ntfs_readonly(dev: BlockDev, mountpoint: AbsPath)` — mountpoint must be under `/run/signalman-privhelper/mounts/`.
   - `unmount(mountpoint: AbsPath)`.
   - `capability_self_check()` → `CapabilityReport` (which ops are functional in this environment).
6. **Audit log:** every op call writes a structured row to journald (`signalman-privhelper.service` unit; structured fields `op`, `caller_pid`, `caller_uid`, `args_sanitized`, `result`, `latency_ms`). Operator inspects via `journalctl -u signalman-privhelper`.
7. **Idempotency:** every op is idempotent. Re-running is a no-op + records `already_satisfied` in the result. Cleanup-on-disconnect re-locks any temporary state (vmlinuz re-locked when last libguestfs op completes).
8. **Distribution:** signed `.deb` (apt) + signed `.rpm` (dnf/yum). Signing via WS9 ml-dsa-65 hybrid signatures. Package install adds a `signalman` group, configures the systemd unit, sets the socket file mode.
9. **`host-deps.yaml` manifest:** lives at repo root (`signalman.host-deps.yaml`). Captured at every workstream's start so a fresh host can replay the same prep. Default contents for Linux:
   ```yaml
   linux:
     packages:
       - libguestfs-tools
       - swtpm
       - ovmf
       - qemu-utils
       - qemu-kvm
       - libvirt-daemon-system
       - libvirt-clients
       - ntfs-3g
     groups:
       - libvirt
       - kvm
       - signalman
     kernel:
       vmlinuz_readable_temporarily: true   # daemon-orchestrated, not permanent
     modules:
       - nbd
     pools:
       - name: user-pool
         path: $HOME/libvirt-images
         autostart: true
     networks:
       - name: default
         autostart: true
   ```
10. **No polkit dependency at MVP.** Polkit integration is a v0.7.1 stretch for desktop operators; agent + headless flows use SO_PEERCRED directly.
